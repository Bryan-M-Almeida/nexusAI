CÓMO USAR ESTE DOCUMENTO
------------------------
Cada error tiene un identificador único con el formato NX-<ÁREA>-<NÚMERO>.
Usa el ID al abrir incidencias, en los commits ("fix NX-LLM-003: ...") y al
hablar con el equipo. Áreas:

  LLM  - Núcleo de IA (Ollama / LM Studio / modelos)
  VOZ  - Reconocimiento de voz (Whisper) y síntesis de voz (SAPI)
  DAT  - Base de datos, memoria y base de conocimiento
  UI   - Interfaz de escritorio (pywebview / WebView2)
  INT  - Integración con la landing page (perfil JSON / puente local)
  ENV  - Entorno, instalación y compilación del ejecutable

(Los IDs son idénticos en las tres versiones de idioma.)

Campos de cada entrada:
  Gravedad   : CRÍTICA (impide el uso) · ALTA (función principal rota)
               MEDIA (funciona con fallos) · BAJA (estético / poco frecuente)
  Estado     : CORREGIDO (resuelto en el código) · MITIGADO (reducido, aún
               puede ocurrir) · CONOCIDO (limitación actual, con solución
               provisional) · PENDIENTE (requiere acción del equipo)
  Observado  : SÍ = reproducido en las pruebas del 2026-10-13 ·
               PREVISTO = riesgo identificado por análisis, no reproducido

Entorno de referencia de las pruebas: Windows 11 Pro, AMD Radeon RX 6600 XT
(8 GB), 16 GB de RAM, Python 3.14.8, Ollama 0.40.3 (backend Vulkan), modelos
qwen2.5:7b y qwen3:8b.


DIAGNÓSTICO RÁPIDO (ejecuta estos comandos antes de investigar)
---------------------------------------------------------------
  ollama --version                         -> ¿Ollama instalado?
  curl http://localhost:11434/api/version  -> ¿responde el servidor de IA?
  ollama list                              -> modelos descargados
  ollama ps                                -> modelo cargado y PROCESSOR
                                              (debe ser "100% GPU")

                                              errores)
  curl http://127.0.0.1:47800/status       -> ¿puente local de NEXUS activo?
  set NEXUS_DEBUG=1 && python run_nexus.py -> abre las DevTools de la interfaz
  Carpeta de datos: .\data (desarrollo) o %LOCALAPPDATA%\NEXUS (instalado)

[NX-LLM-001] IA sin conexión: servidor Ollama no encontrado
  Gravedad   : CRÍTICA          Estado: CONOCIDO           Observado: SÍ
  Síntoma    : Indicador "IA" en rojo en la barra superior; mensaje "Mi
               núcleo de IA está fuera de línea" con cualquier comando. El
               paso "NÚCLEO DE IA" del arranque aparece con "!!".
  Causa      : Ollama no instalado, no iniciado, o URL incorrecta en
               Configuración (llm_base_url).
  Solución   : 1. Instala: winget install Ollama.Ollama
               2. Comprueba: curl http://localhost:11434/api/version
               3. Si no responde, abre Ollama desde el menú Inicio o ejecuta
                  "ollama serve" en una terminal.
               4. En la Configuración de NEXUS la URL debe ser
                  http://localhost:11434/v1 (Ollama) o
                  http://localhost:1234/v1 (LM Studio).
  Consejos   : NEXUS sigue funcionando sin IA para agenda, tareas, memoria y
               conocimiento desde los paneles; solo el chat depende de ella.

[NX-LLM-002] El modelo configurado no está descargado
  Gravedad   : CRÍTICA          Estado: CONOCIDO           Observado: SÍ
  Síntoma    : Mensaje "Servidor en línea, pero el modelo X no está
               descargado".
  Causa      : El modelo de Configuración no aparece en "ollama list".
  Solución   : ollama pull qwen3:8b   (predeterminado actual, ~5,2 GB)
  Consejos   : El nombre debe coincidir exactamente (incluida la etiqueta
               ":8b"). El campo Modelo de Configuración lista los modelos
               instalados.

[NX-LLM-003] La IA afirma haber hecho acciones sin llamar a herramientas
  Gravedad   : ALTA             Estado: MITIGADO           Observado: SÍ
  Síntoma    : Respuestas como "Registré tus gastos", "Recordaré que eres
               alérgico" o "Aprendí el horario" sin nada guardado en la base
               de datos (paneles Memoria/Datos/Saber vacíos).
  Causa      : (a) qwen2.5:7b ignoró las herramientas record_data, remember y
               learn_knowledge en el 100% de las pruebas;
               (b) el contexto truncado (ver NX-LLM-004) eliminaba las
               instrucciones; (c) los modelos pequeños a veces "fingen" la
               acción.
  Correcciones: - Modelo predeterminado cambiado a qwen3:8b (llamó
                 correctamente a todas las herramientas en las pruebas).
               - Reglas explícitas en el prompt ("LAS ACCIONES REQUIEREN
                 LLAMAR A UNA HERRAMIENTA") con el mapa intención ->
                 herramienta.
               - Red de seguridad (assistant.py, _needs_tool): si la respuesta
                 afirma una acción ("registrei", "aprendeu", "saved",
                 "guardé"...) y no se llamó a ninguna herramienta, NEXUS
                 devuelve el mensaje al modelo exigiendo la llamada (1 vez).
  Cómo verificar: los indicadores "⚙ ..." aparecen sobre la respuesta cuando
               se ejecuta una herramienta. Sin indicador = no se guardó nada.
  Consejos   : Si ocurre a menudo, baja llm_temperature a 0.1 en
               data\settings.json. Evita modelos de menos de 7-8B para usar
               herramientas. Al añadir frases de confirmación en otros
               idiomas, actualiza la regex CLAIMED de assistant.py.
  v0.4       : La red de seguridad también revisa la PETICIÓN del usuario: si
               dijo "aprende que", "recuerda que", "recuérdame" o "registra" y
               no se llamó a la herramienta correspondiente, NEXUS exige la
               llamada (caso real: "Aprenda que o wifi..." solo se repetía).

[NX-LLM-004] Contexto truncado a 4096 tokens por la API /v1 de Ollama
  Gravedad   : ALTA             Estado: CORREGIDO          Observado: SÍ
  Síntoma    : El modelo ignora reglas y herramientas; "ollama ps" muestra
               CONTEXT 4096.
  Causa      : La ruta compatible con OpenAI (/v1/chat/completions) de Ollama
               no acepta num_ctx y usa el valor por defecto de 4096 tokens. El
               prompt de NEXUS (reglas + 21 herramientas + contexto) supera
               los 2.500 tokens y crece con el historial; se descartaba el
               principio.
  Corrección : llm.py usa la API nativa de Ollama (/api/chat) cuando la URL es
               :11434 (llm_provider = "auto"), enviando
               options.num_ctx = llm_context (por defecto 8192).
  Consejos   : Con LM Studio (provider "openai"), configura el "Context
               Length" del modelo en 8192 o más en el propio LM Studio.
               Alternativa global para Ollama: variable de entorno
               OLLAMA_CONTEXT_LENGTH=8192.

[NX-LLM-005] Fechas relativas resueltas al día equivocado
  Gravedad   : ALTA             Estado: CORREGIDO          Observado: SÍ
  Síntoma    : "Agenda una reunión el viernes" creaba el evento el
               2026-10-20 (martes) en lugar del 2026-10-16 (viernes).
  Causa      : Los modelos de lenguaje calculan mal el día de la semana a
               partir de una fecha.
  Corrección : El contexto de cada mensaje incluye un calendario listo de los
               próximos 8 días ("viernes 2026-10-16; ...") y la regla "nunca
               calcules días de la semana, usa el calendario".
  Consejos   : Para fechas a más de 8 días, revisa el evento en el panel
               Agenda. Las fechas absolutas ("el día 25 a las 14 h") siempre
               son más fiables.

[NX-LLM-006] Respuesta en el idioma equivocado
  Gravedad   : MEDIA            Estado: MITIGADO           Observado: SÍ
  Síntoma    : Pregunta en inglés respondida en portugués.
  Causa      : El prompt de sistema pide el idioma del perfil y el modelo
               priorizaba esa regla sobre el idioma del mensaje.
  Corrección : i18n.detect() identifica pt/en/es por palabras frecuentes y el
               contexto indica "responde SOLO en <idioma>".
  Limitación : Los mensajes muy cortos ("ok", "gracias") o mezclados no se
               detectan; en ese caso se usa el idioma del perfil/
               configuración.
  Consejos   : Fija el idioma en Configuración > Idioma si el usuario usa
               siempre el mismo. Para nuevos idiomas, amplía _MARKERS en
               i18n.py.

[NX-LLM-007] Días de la semana traducidos incorrectamente
  Gravedad   : MEDIA            Estado: CORREGIDO          Observado: SÍ
  Síntoma    : "Quarta-feira 14" (miércoles) mostrado como "terça-feira"
               (martes) y el viernes como sábado en respuestas en portugués.
  Causa      : El contexto enviaba los días en inglés y el modelo los
               traducía mal.
  Corrección : Los días de la semana se envían ya en el idioma del mensaje
               (i18n.WEEKDAYS).

[NX-LLM-008] Narración intermedia y bloques JSON en la respuesta
  Gravedad   : MEDIA            Estado: CORREGIDO          Observado: SÍ
  Síntoma    : Respuestas con "Voy a listar tus tareas..." seguido de bloques
               ```json``` y texto repetido.
  Causa      : El texto generado antes de cada llamada a herramienta se sumaba
               a la respuesta final.
  Corrección : Solo el texto de la última ronda (sin herramientas) es la
               respuesta; la interfaz recibe el evento "reset" y borra la
               narración, manteniendo los indicadores de herramientas. Regla
               en el prompt: "nunca muestres JSON, nombres de herramientas ni
               pasos internos".

[NX-LLM-009] La plantilla del modelo descarta mensajes de sistema extra
  Gravedad   : ALTA             Estado: CORREGIDO          Observado: SÍ
  Síntoma    : Reglas ignoradas tras mover el contexto a un segundo mensaje
               "system"; caché del prompt invalidada en cada turno.
  Causa      : La plantilla de chat de qwen2.5 en Ollama solo muestra UN
               mensaje de sistema (al principio) e ignora los demás. Además,
               un mensaje de asistente con texto + tool_calls pierde las
               llamadas en la plantilla.
  Corrección : El contexto dinámico va dentro del mensaje del usuario del
               turno actual (<context>...</context>); el historial guarda solo
               el texto original. Los mensajes de llamada a herramientas se
               envían con contenido vacío.
  Consejos   : Al probar un modelo nuevo, revisa su plantilla con
               "ollama show <modelo> --template".

[NX-LLM-010] Respuestas lentas (10 a 25 segundos)
  Gravedad   : MEDIA            Estado: MITIGADO           Observado: SÍ
  Síntoma    : Cada respuesta tarda de 10 a 25 s en el hardware de
               referencia; las respuestas largas (p. ej. primeros auxilios)
               hasta ~25 s.
  Causa      : El procesamiento del prompt en la RX 6600 XT vía Vulkan fue de
               ~100-220 tokens/s. Cada mensaje envía ~300-1.200 tokens nuevos
               (contexto + pregunta). Las llamadas a herramientas requieren
               una segunda ronda del modelo.
  Correcciones: - Prompt dividido en una parte fija (reglas, perfil,
                 herramientas), que queda en la caché de Ollama, y un
                 contexto por mensaje. Medido: un prompt idéntico bajó de
                 12,5 s a 0,6 s.
               - Los fragmentos de conocimiento solo entran en el contexto
                 cuando la búsqueda es realmente relevante (BM25 <= -7.5, máx.
                 2 fragmentos).
               - keep_alive de 30 min mantiene el modelo cargado en la VRAM.
  Consejos   : 1. Actualiza el controlador AMD Adrenalin (ver NX-LLM-013): es
                  la mejora de rendimiento más probable.
               2. Modelo más pequeño para PCs modestos: ollama pull qwen3:4b
                  y cámbialo en Configuración (menos preciso con
                  herramientas).
               3. Reduce history_turns (por defecto 12) en
                  data\settings.json.
               4. Prueba OLLAMA_FLASH_ATTENTION=1 (variable de entorno,
                  reinicia Ollama) y compara los tiempos.
               5. Cierra juegos/apps que usen la GPU.

[NX-LLM-011] La primera respuesta tras abrir la app es muy lenta
  Gravedad   : BAJA             Estado: CONOCIDO           Observado: SÍ
  Síntoma    : El primer mensaje tarda 15-35 s; los siguientes son más
               rápidos.
  Causa      : Carga del modelo (~5 GB) en la VRAM y primer procesamiento de
               todo el prompt fijo.
  Solución provisional: Espera la primera respuesta. Mejora prevista:
               "calentar" el modelo durante la animación de arranque con una
               petición vacía.

[NX-LLM-012] Comportamiento inconsistente entre ejecuciones
  Gravedad   : MEDIA            Estado: CONOCIDO           Observado: SÍ
  Síntoma    : La misma petición funciona en una ejecución y falla en otra.
               P. ej.: "¿qué compromisos tengo?" listó 2 eventos en una
               ronda y solo 1 en otra; "Aprende que..." a veces no llamó a la
               herramienta.
  Causa      : Generación probabilística (temperatura 0.3) de un modelo de
               8B.
  Mitigación : Reglas explícitas, red de seguridad (NX-LLM-003), contexto con
               la agenda ya formateada.
  Consejos   : llm_temperature = 0.1 hace el modelo más predecible. Para
               demostraciones (p. ej. el jurado del hackathon), ensaya los
               comandos exactos que vas a usar.

[NX-LLM-013] Aviso "AMD driver is too old" en el registro de Ollama
  Gravedad   : BAJA             Estado: PENDIENTE          Observado: SÍ
  Síntoma    : server.log contiene "AMD driver is too old. Update your AMD
               driver to enable GPU inference."
  Causa      : El backend ROCm de Ollama requiere un controlador más reciente.
               Al no estar disponible, Ollama usa el backend Vulkan (que
               funcionó: "library=Vulkan ... AMD Radeon RX 6600 XT",
               "100% GPU").
  Solución   : Actualizar AMD Software: Adrenalin Edition desde la web de
               AMD. Acción manual del usuario (NEXUS nunca modifica
               controladores).
  Consejos   : Tras actualizar, reinicia Ollama, comprueba en server.log qué
               biblioteca se eligió (ROCm o Vulkan) y compara los tiempos de
               respuesta.

[NX-LLM-014] Modelo ejecutándose en parte en la CPU (VRAM insuficiente)
  Gravedad   : ALTA             Estado: CONOCIDO           Observado: PREVISTO
  Síntoma    : "ollama ps" muestra PROCESSOR como "40%/60% CPU/GPU" y las
               respuestas se vuelven muy lentas (minutos).
  Causa      : El modelo + el contexto no caben en la VRAM libre (otras apps
               usando la GPU, tarjetas con menos de 8 GB).
  Solución   : Usa un modelo más pequeño (qwen3:4b), reduce llm_context a
               4096 (puede empeorar NX-LLM-004) o cierra las apps que usan la
               GPU.

[NX-LLM-015] El modo de razonamiento (thinking) hace lento a qwen3
  Gravedad   : MEDIA            Estado: CORREGIDO          Observado: PREVISTO
  Causa      : qwen3 "piensa" antes de responder por defecto, generando
               cientos de tokens extra.
  Corrección : llm.py envía "think": false en la API nativa de Ollama.
  Consejos   : Con LM Studio (API OpenAI) el parámetro no se envía: añade
               "/no_think" a las instrucciones del sistema o desactiva el
               razonamiento en la interfaz de LM Studio.

[NX-LLM-016] La memoria automática guarda datos redundantes o genéricos
  Gravedad   : BAJA             Estado: CONOCIDO           Observado: SÍ
  Síntoma    : Memorias como "El usuario prefiere trabajar de madrugada"
               parecidas a otras ya existentes.
  Causa      : La extracción automática se ejecuta tras cada conversación y la
               eliminación de duplicados solo compara texto idéntico.
  Solución provisional: Elimina elementos con "✕" en el panel Memoria o
               desactiva "Memorizar hechos automáticamente" en Configuración.
  Mejora     : Deduplicación semántica con embeddings (hoja de ruta).

[NX-LLM-017] El modelo inventa argumentos de herramientas
  Gravedad   : MEDIA            Estado: CORREGIDO          Observado: SÍ
  Síntoma    : Llamadas como list_events(status="pending") generaban errores
               y el modelo repetía la llamada varias veces.
  Corrección : tools.execute() descarta los parámetros que la función no
               acepta y los valores nulos antes de ejecutar.


[NX-LLM-018] La IA resuelve "repite"/"explica mejor" conversando, sin la herramienta
  Gravedad   : BAJA             Estado: CONOCIDO           Observado: SÍ
  Síntoma    : Ante peticiones largas ("¿puedes repetir lo que acabas de
               decir?", "no entendí nada, explícalo más simple"), qwen3:8b
               responde directamente sin llamar a conversation_control.
  Impacto    : En las pruebas el resultado fue correcto (repitió / volvió a
               explicar de forma más simple / confirmó que se quedaría
               callado). Las acciones que deben actuar sobre el audio (pausar,
               parar, continuar, repetir) las gestiona el detector local
               (nexus/control.py), que es instantáneo y no depende del modelo.
  Consejos   : Los comandos cortos o que EMPIEZAN con "espera un momento",
               "para de hablar", "basta"... siempre se reconocen. Para nuevas
               expresiones, edita PATTERNS/LEADING en nexus/control.py.

[NX-LLM-019] Pregunta ambigua respondida con un tema de otra conversación
  Gravedad   : ALTA             Estado: CORREGIDO (v0.4)   Observado: SÍ
  Síntoma    : Conversación real del 2026-10-13: tras preguntar el peso del
               corazón, "dime los valores exactos" se respondió con "Gastaste
               R$ 18,00 en el almuerzo y R$ 42,00 en el mercado".
  Causa      : (1) el historial enviado a la IA eran los últimos 24 mensajes
               sin límite de tiempo, incluida una conversación sobre gastos de
               una hora antes; (2) el registro de acciones recientes
               ("Registró en 'gastos'...") iba en el contexto de cada mensaje;
               (3) "valores" es ambiguo y el modelo de 8B eligió el "valor"
               más llamativo (dinero).
  Corrección : - historial solo de la sesión actual (desde que se abrió la app;
                 2 h de silencio también terminan la sesión) -
                 memory.session_start();
               - registro de acciones solo de la sesión y de los últimos 15
                 minutos;
               - regla: las preguntas cortas/elípticas se refieren a la última
                 respuesta;
               - la búsqueda en la base usa también la pregunta anterior si el
                 mensaje tiene menos de 6 palabras.
  Cómo verificar: tests\conversation_eval.py reproduce el caso con una sesión
               antigua de gastos colocada 3 h antes.

[NX-LLM-020] Valores imprecisos o contradictorios en preguntas factuales
  Gravedad   : MEDIA            Estado: MITIGADO           Observado: SÍ
  Síntoma    : "El corazón de una mujer pesa entre 250 y 350 g, similar al del
               hombre" y luego "250 a 300 g" (contradicción). Valores de
               referencia: hombre ~280-340 g, mujer ~230-280 g.
  Causa      : La base no tenía anatomía; el modelo respondió "de memoria", y
               los modelos de 8B son imprecisos con los números. Tampoco dijo
               que no existe un "valor exacto".
  Corrección : - libro "Anatomía" (PT/EN/ES) con pesos de órganos, signos
                 vitales, sangre, huesos y valores de referencia;
               - regla: dar media y rango, decir cuando no hay valor exacto,
                 ser coherente y corregirse explícitamente.
  Limitación : Fuera de los temas de la base, el modelo aún puede fallar con
               los números. Enseña a NEXUS fuentes fiables (botón Enseñar /
               inbox).

[NX-VOZ-001] El micrófono no responde en el primer uso (descarga Whisper)
  Gravedad   : MEDIA            Estado: CONOCIDO           Observado: PREVISTO
  Síntoma    : Al pulsar el micrófono aparece "Preparando el modelo de
               voz...".
  Causa      : El modelo Whisper se descarga solo en el primer uso (tiny
               ~75 MB, base ~145 MB, small ~480 MB, medium ~1,5 GB) para no

  Solución   : Espera la descarga (requiere internet una vez) y pulsa de

  Consejos   : Para PCs sin internet, abre NEXUS una vez con conexión y usa

               (%USERPROFILE%\.cache\huggingface). Si la descarga falla, el
               error aparece en el chat; cambia a "base" en Configuración.

[NX-VOZ-002] Micrófono equivocado seleccionado (p. ej. DroidCam)
  Gravedad   : ALTA             Estado: PENDIENTE          Observado: SÍ
  Síntoma    : NEXUS no reacciona al habla o graba silencio.
  Causa      : NEXUS usa el dispositivo de entrada PREDETERMINADO de
               Windows. En el PC de referencia era "Micrófono (DroidCam
               Audio)", un micrófono virtual.
  Solución   : Configuración de Windows > Sistema > Sonido > Entrada: elige el
               micrófono real como predeterminado y reinicia NEXUS.
  Mejora     : Añadir la selección de dispositivo en la Configuración de
               NEXUS (sounddevice.query_devices).

[NX-VOZ-003] Palabra de activación "Nexus" no reconocida / falsos disparos
  Gravedad   : MEDIA            Estado: CONOCIDO           Observado: PREVISTO
  Síntoma    : Decir "Nexus" no lo activa; o NEXUS responde a
               conversaciones paralelas.
  Causa      : Whisper transcribe "Nexus" de varias formas ("Néxus", "Nexos",
               "Next us"). La regex WAKE_RE de voice.py cubre las variantes
               más comunes.
  Consejos   : Di "Nexus" y haz una pausa breve antes del comando. Usa el
               modelo "small" (más preciso que "base"/"tiny"). Si aparece
               una variante nueva, añádela a WAKE_RE. En lugares ruidosos,
               prefiere el botón del micrófono o Ctrl+Espacio.

[NX-VOZ-004] La grabación no empieza o no termina (detección de voz)
  Gravedad   : MEDIA            Estado: CONOCIDO           Observado: PREVISTO
  Síntoma    : El estado se queda en "ESCUCHANDO" indefinidamente, o no se
               capta el habla.
  Causa      : La detección de voz usa la energía de la señal con un umbral
               adaptado al ruido ambiente. Ventiladores, música o una
               ganancia del micrófono muy baja/alta interfieren.
  Consejos   : La grabación termina tras ~0,75 s de silencio o 30 s como
               máximo. Ajusta el volumen del micrófono en Windows a ~70-80%.
               Usa auriculares con micrófono en entornos ruidosos.

[NX-VOZ-005] NEXUS oye su propia voz (eco)
  Gravedad   : MEDIA            Estado: MITIGADO           Observado: PREVISTO
  Causa      : Altavoces captados por el micrófono mientras NEXUS habla.
  Mitigación : Desde la v0.3, mientras NEXUS habla el micrófono sigue activo
               pero solo acepta comandos de control cortos ("pausa", "para",
               "espera un momento...") de hasta 4 s; el resto se ignora (ver
               NX-VOZ-013). Al terminar de hablar hay 250 ms de margen.
  Consejos   : Usa auriculares; silencia la voz de la IA desde la barra si es
               necesario.

[NX-VOZ-006] Sin voz en español / voz en el idioma equivocado
  Gravedad   : MEDIA            Estado: PENDIENTE          Observado: SÍ
  Síntoma    : Respuestas en español leídas con la voz en portugués/inglés.
  Causa      : Solo se usan las voces SAPI instaladas. El PC de referencia
               tiene Maria (pt-BR, femenina), Daniel (pt-BR, masculina,
               OneCore) y Zira (en-US, femenina); ninguna en español.
  Solución   : Configuración de Windows > Hora e idioma > Voz > Agregar
               voces > Español. Reinicia NEXUS. Las voces instaladas aparecen

[NX-VOZ-007] La síntesis de voz deja de funcionar al cabo de un tiempo
  Gravedad   : MEDIA            Estado: CORREGIDO          Observado: PREVISTO
  Causa      : Problema conocido de pyttsx3 con llamadas repetidas a
               runAndWait() en algunos sistemas.
  Corrección : pyttsx3 se sustituyó por un motor propio (nexus/tts.py): SAPI
               genera el audio en memoria y sounddevice lo reproduce. Si la voz
               falla, el error queda en Speaker.error y la app continúa.

[NX-VOZ-008] Transcripción lenta
  Gravedad   : BAJA             Estado: CONOCIDO           Observado: PREVISTO
  Causa      : Whisper se ejecuta en la CPU (CTranslate2 no usa GPUs AMD en
               Windows).
  Consejos   : Usa "base" en Configuración para más velocidad y "small" para
               más precisión. Las frases cortas se transcriben más rápido.

[NX-VOZ-009] "Silenciar" solo interrumpe al final de la frase actual
  Gravedad   : BAJA             Estado: CORREGIDO          Observado: PREVISTO
  Causa      : Con pyttsx3 la interrupción solo ocurría entre frases.
  Corrección : Con el motor nuevo, Esc / "silenciar" llaman a
               sounddevice.stop() y cortan el audio de inmediato.

[NX-VOZ-010] La voz masculina suena andrógina en algunos idiomas
  Gravedad   : BAJA             Estado: CONOCIDO           Observado: SÍ
  Síntoma    : Con "Voz: masculina" en inglés, el habla suena entre masculina
               y femenina.
  Causa      : No hay voz masculina instalada para ese idioma (el PC de
               referencia solo tiene Zira en inglés). NEXUS usa la voz
               disponible con el tono más grave (pitch -8, ~190 Hz -> ~150 Hz).
  Solución   : Instala una voz masculina del idioma (p. ej. "Microsoft David"
               o "Microsoft Mark" para inglés) en Configuración de Windows >
               Hora e idioma > Voz. La Configuración de NEXUS avisa cuando el
               género elegido no existe para el idioma actual.

[NX-VOZ-011] El efecto de voz "J.A.R.V.I.S"/"Robot" suena apagado o demasiado metálico
  Gravedad   : BAJA             Estado: CONOCIDO           Observado: PREVISTO
  Causa      : Los efectos varían mucho según el altavoz. Desde la v0.4
               "J.A.R.V.I.S" es limpio (realce de presencia 2-5 kHz, brillo de
               1,2 ms y ambiente corto, sin modulación en anillo); "Robot"
               mantiene a propósito la modulación en anillo y el filtro
               metálico.
  Consejos   : Usa "J.A.R.V.I.S" a diario y "Robot" solo como efecto.
               "Natural" desactiva el procesamiento. Para ajustarlo, edita
               apply_effect() (nexus/tts.py) y usa "Probar voz".

[NX-VOZ-012] Los comandos durante el habla fallan con altavoces
  Gravedad   : MEDIA            Estado: CONOCIDO           Observado: PREVISTO
  Síntoma    : "Pausa" dicho mientras NEXUS habla no se reconoce.
  Causa      : Sin cancelación de eco, el micrófono capta la voz de NEXUS
               junto con la del usuario y Whisper transcribe la mezcla.
  Solución   : Usa auriculares; o usa los botones de la barra (interrumpir) y
               Esc. Mejora futura: cancelación de eco (AEC).

[NX-VOZ-013] Una frase dicha mientras NEXUS habla se ignora
  Gravedad   : BAJA             Estado: CONOCIDO           Observado: SÍ
  Comportamiento esperado: mientras habla, solo se aceptan comandos de
               control (pausar, parar, repetir, no entendí...). Así NEXUS no
               se responde a sí mismo por el eco.
  Solución provisional: Di "pausa" o "para" y luego pregunta, o espera a que
               termine. En pausa, el micrófono vuelve a aceptar cualquier
               frase.

[NX-VOZ-014] El modo "solo audio" responde a conversaciones cercanas / TV
  Gravedad   : MEDIA            Estado: CONOCIDO           Observado: PREVISTO
  Causa      : Desde la v0.3 el modo audio escucha de forma continua sin
               exigir la palabra "Nexus".
  Solución   : Activa "Responder solo cuando diga Nexus" en Configuración,

[NX-VOZ-015] Voz de "aparato de fumador" (laringe electrónica), difícil de entender
  Gravedad   : ALTA             Estado: CORREGIDO (v0.4)   Observado: SÍ
  Causa      : El efecto J.A.R.V.I.S (v0.2-v0.3) multiplicaba la voz por un
               tono de 45 Hz (modulación en anillo), además de un filtro
               metálico y un corte por encima de 7 kHz. Medido: zumbido 16 a
               24 veces por encima de la voz natural y consonantes sin realce.
  Corrección : Efecto nuevo sin modulación: realce de presencia en 2-5 kHz,
               brillo de 1,2 ms y ambiente corto. Medido: zumbido 1,2-1,5x,
               fidelidad 0,88 -> 0,97, energía de las consonantes ~2x.
  Cómo verificar: tests\test_units.py lo compara con la modulación antigua.

[NX-VOZ-016] Nombre pronunciado "NÊXUS" (o deletreado "N, E, X, U, S")
  Gravedad   : BAJA             Estado: CORREGIDO (v0.4.1) Observado: SÍ
  Causa      : Las voces en portugués/español leen "Nexus" con E cerrada y

  Corrección : El texto enviado a la voz cambia el nombre por una grafía

               (Daniel) y "Néc-sus" para la femenina (Maria). "Néxus" (v0.4.0)

               N.E.X.U.S (tts.pronounce()).
  Consejos   : Para una voz nueva, prueba grafías y ajusta _SPOKEN_NAME en
               nexus/tts.py; compruébalo siempre de oído.

[NX-DAT-008] El saludo "¿continuamos con...?" no aparece / aparece solo una vez
  Gravedad   : BAJA             Estado: CONOCIDO           Observado: SÍ

               NEXUS, recuérdame continuar el proyecto X".
  Para ver de nuevo la presentación: borra la fila "introduced" de la tabla
               state (o usa un NEXUS_HOME nuevo).
