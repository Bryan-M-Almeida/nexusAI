HOW TO USE THIS DOCUMENT
------------------------
Each issue has a unique identifier in the format NX-<AREA>-<NUMBER>.
Use the ID when opening issues, in commits ("fix NX-LLM-003: ...") and when
talking to the team. Areas:

  LLM  - AI core (Ollama / LM Studio / models)
  VOZ  - Speech recognition (Whisper) and speech synthesis (SAPI)
  DAT  - Database, memory and knowledge base
  UI   - Desktop interface (pywebview / WebView2)
  WRK  - Workspace (isolated projects, the AI's files and commands)
  INT  - Landing page integration (JSON profile / local bridge)
  ENV  - Environment, installation and executable build

(The IDs are identical in the three language versions; "VOZ" means voice.)

Fields of each entry:
  Severity : CRITICAL (blocks usage) · HIGH (core feature broken)
             MEDIUM (works with flaws) · LOW (cosmetic / rare)
  Status   : FIXED (solved in code) · MITIGATED (reduced, may still occur)
             · KNOWN (current limitation, with workaround)
             · PENDING (requires action from the team)
  Observed : YES = reproduced in the 2026-10-13 tests ·
             EXPECTED = risk identified by analysis, not reproduced

Reference test environment: Windows 11 Pro, AMD Radeon RX 6600 XT (8 GB),
16 GB RAM, Python 3.14.8, Ollama 0.40.3 (Vulkan backend), models qwen2.5:7b
and qwen3:8b.


QUICK DIAGNOSTICS (run these before investigating)
--------------------------------------------------
  ollama --version                         -> is Ollama installed?
  curl http://localhost:11434/api/version  -> is the AI server responding?
  ollama list                              -> downloaded models
  ollama ps                                -> loaded model and PROCESSOR
                                              (should be "100% GPU")
  %LOCALAPPDATA%\Ollama\server.log         -> server log (GPU, errors)
  curl http://127.0.0.1:47800/status       -> is the NEXUS local bridge up?
  set NEXUS_DEBUG=1 && python run_nexus.py -> opens the UI DevTools
  Data folder: .\data (development) or %LOCALAPPDATA%\NEXUS (installed)

[NX-LLM-001] AI offline: Ollama server not found
  Severity   : CRITICAL         Status: KNOWN              Observed: YES
  Symptom    : "AI" chip is red in the top bar; message "My AI core is
               offline" on any command. Boot step "AI CORE" marked "!!".
  Cause      : Ollama not installed, not running, or wrong URL in Settings
               (llm_base_url).
  Solution   : 1. Install: winget install Ollama.Ollama
               2. Check: curl http://localhost:11434/api/version
               3. If it doesn't respond, open Ollama from the Start menu or
                  run "ollama serve" in a terminal.
               4. In NEXUS Settings the URL must be
                  http://localhost:11434/v1 (Ollama) or
                  http://localhost:1234/v1 (LM Studio).
  Tips       : NEXUS keeps working without AI for schedule, tasks, memory and
               knowledge through the panels; only the chat depends on it.

[NX-LLM-002] Configured model is not downloaded
  Severity   : CRITICAL         Status: KNOWN              Observed: YES
  Symptom    : Message "Server online, but model X is not downloaded".
  Cause      : The model set in Settings does not appear in "ollama list".
  Solution   : ollama pull qwen3:8b   (current default, ~5.2 GB)
  Tips       : The name must match exactly (including the ":8b" tag).
               The Model field in Settings lists the installed models.

[NX-LLM-003] AI claims to have performed actions without calling tools
  Severity   : HIGH             Status: MITIGATED          Observed: YES
  Symptom    : Replies such as "I logged your expenses", "I'll remember you
               are allergic" or "I learned the hours" with nothing saved in
               the database (Memory/Data/Knowledge panels empty).
  Cause      : (a) qwen2.5:7b ignored the record_data, remember and
               learn_knowledge tools in 100% of the tests;
               (b) truncated context (see NX-LLM-004) removed the
               instructions; (c) small models sometimes "pretend" to act.
  Fixes      : - Default model switched to qwen3:8b (called every tool
                 correctly in the tests).
               - Explicit prompt rules ("ACTIONS REQUIRE TOOL CALLS") with an
                 intent -> tool map.
               - Safety net (assistant.py, _needs_tool): if the reply claims
                 an action ("registrei", "aprendeu", "saved", "guardé"...)
                 and no tool was called, NEXUS sends the message back to the
                 model demanding the call (once).
  How to check: "⚙ ..." chips appear above the reply when a tool runs.
               No chip = nothing was saved.
  Tips       : If it happens often, lower llm_temperature to 0.1 in
               data\settings.json. Avoid models smaller than 7-8B for tool
               use. When adding confirmation phrases in other languages,
               update the CLAIMED regex in assistant.py.
  v0.4       : The safety net also checks the user's REQUEST: if they said
               "learn that", "remember that", "remind me" or "log/record" and
               the matching tool was not called, NEXUS demands the call (real
               case: "Aprenda que o wifi..." was only echoed back).

[NX-LLM-004] Context truncated to 4096 tokens by Ollama's /v1 API
  Severity   : HIGH             Status: FIXED              Observed: YES
  Symptom    : The model ignores rules and tools; "ollama ps" shows
               CONTEXT 4096.
  Cause      : Ollama's OpenAI-compatible route (/v1/chat/completions) does
               not accept num_ctx and uses the 4096-token default. The NEXUS
               prompt (rules + 21 tools + context) exceeds 2,500 tokens and
               grows with history; the beginning was being dropped.
  Fix        : llm.py uses Ollama's native API (/api/chat) when the URL is
               :11434 (llm_provider = "auto"), sending
               options.num_ctx = llm_context (default 8192).
  Tips       : With LM Studio (provider "openai"), set the model "Context
               Length" to 8192 or more in LM Studio itself. Global
               alternative for Ollama: environment variable
               OLLAMA_CONTEXT_LENGTH=8192.

[NX-LLM-005] Relative dates resolved to the wrong day
  Severity   : HIGH             Status: FIXED              Observed: YES
  Symptom    : "Schedule a meeting on Friday" created the event on
               2026-10-20 (Tuesday) instead of 2026-10-16 (Friday).
  Cause      : Language models are bad at computing weekdays from a date.
  Fix        : Each message's context includes a ready-made calendar of the
               next 8 days ("Friday 2026-10-16; ...") and the rule "never
               compute weekdays, use the calendar".
  Tips       : For dates beyond 8 days, check the event in the Schedule
               panel. Absolute dates ("the 25th at 2 pm") are always more
               reliable.

[NX-LLM-006] Reply in the wrong language
  Severity   : MEDIUM           Status: MITIGATED          Observed: YES
  Symptom    : Question in English answered in Portuguese.
  Cause      : The system prompt asks for the profile language and the model
               prioritized that rule over the message language.
  Fix        : i18n.detect() identifies pt/en/es from frequent words and the
               context instructs "reply ONLY in <language>".
  Limitation : Very short ("ok", "thanks") or mixed messages are not
               detected; the profile/settings language applies then.
  Tips       : Pin the language in Settings > Language if the user always
               uses the same one. For new languages, extend _MARKERS in
               i18n.py.

[NX-LLM-007] Weekday names translated incorrectly
  Severity   : MEDIUM           Status: FIXED              Observed: YES
  Symptom    : "Quarta-feira 14" (Wednesday) shown as "terça-feira"
               (Tuesday), Friday as Saturday in Portuguese replies.
  Cause      : The context sent weekdays in English and the model
               mistranslated them.
  Fix        : Weekdays are sent already in the message language
               (i18n.WEEKDAYS).

[NX-LLM-008] Intermediate narration and JSON blocks leaking into replies
  Severity   : MEDIUM           Status: FIXED              Observed: YES
  Symptom    : Replies with "Let me list your tasks..." followed by
               ```json``` blocks and repeated text.
  Cause      : Text generated before each tool call was appended to the
               final reply.
  Fix        : Only the text of the last round (without tools) becomes the
               reply; the UI receives a "reset" event and clears the
               narration, keeping the tool chips. Prompt rule: "never show
               JSON, tool names or internal steps".

[NX-LLM-009] Model template drops extra system messages
  Severity   : HIGH             Status: FIXED              Observed: YES
  Symptom    : Rules ignored after moving the context into a second
               "system" message; prompt cache invalidated on every turn.
  Cause      : qwen2.5's chat template in Ollama renders only ONE system
               message (at the top) and ignores the rest. Also, an assistant
               message with text + tool_calls has its calls omitted by the
               template.
  Fix        : The dynamic context goes inside the user message of the
               current turn (<context>...</context>); history stores only the
               original text. Tool-call messages are sent with empty content.
  Tips       : When testing a new model, inspect its template with
               "ollama show <model> --template".

[NX-LLM-010] Slow replies
  Severity   : MEDIUM           Status: MITIGATED (v0.6)   Observed: YES
  Symptom    : Up to v0.5, 10 to 25 s per reply (14.9 s average to the first
               word; 30 s for the first message).
  Cause      : Prompt processing on the RX 6600 XT via Vulkan: ~60-150 tokens/s
               (measured). Each message sent ~370 new context tokens, and each
               Ollama call waited ~2 s extra because of "localhost"
               (NX-ENV-008).
  Fixes      : v0.6 - AI loaded at startup (NX-LLM-011), 127.0.0.1 instead of
               localhost, lean context (only what the message needs, ~210
               tokens on average), streamed speech in audio mode and the model
               kept in GPU memory. Measured: 4.5 s average to the first word
               (was 14.9 s); 11-14 s with an online lookup.
  Tips       : 1. Update the AMD Adrenalin driver (see NX-LLM-013).
               2. Smaller model: ollama pull qwen3:4b (less accurate).
               3. Measure with tests\bench_latency.py --warm.

[NX-LLM-011] First reply after opening the app is very slow
  Severity   : LOW              Status: FIXED (v0.6)       Observed: YES
  Symptom    : The first message took ~30 s (7 s loading the model + 20 s
               processing the fixed part of the prompt).
  Fix        : During the boot animation NEXUS loads the model and processes
               the fixed part of the prompt (assistant.warm_up). The AI chip is
               amber while loading and blue when ready. Measured: first message
               in 1.3 s.
  Limitation : Loading takes ~25 s; if you talk before the chip turns blue,
               the first reply waits for the rest.

[NX-LLM-012] Inconsistent behavior between runs
  Severity   : MEDIUM           Status: KNOWN              Observed: YES
  Symptom    : The same request works in one run and fails in another.
               E.g. "what commitments do I have?" listed 2 events in one run
               and only 1 in another; "Learn that..." sometimes didn't call
               the tool.
  Cause      : Probabilistic generation (temperature 0.3) of an 8B model.
  Mitigation : Explicit rules, safety net (NX-LLM-003), context with the
               schedule already formatted.
  Tips       : llm_temperature = 0.1 makes the model more predictable. For
               demos (e.g. the hackathon judges), rehearse the exact
               commands you will use.

[NX-LLM-013] "AMD driver is too old" warning in the Ollama log
  Severity   : LOW              Status: PENDING            Observed: YES
  Symptom    : server.log contains "AMD driver is too old. Update your AMD
               driver to enable GPU inference."
  Cause      : Ollama's ROCm backend requires a newer driver. With it
               unavailable, Ollama uses the Vulkan backend (which worked:
               "library=Vulkan ... AMD Radeon RX 6600 XT", "100% GPU").
  Solution   : Update AMD Software: Adrenalin Edition from AMD's website.
               Manual user action (NEXUS never changes drivers).
  Tips       : After updating, restart Ollama, check in server.log which
               library was chosen (ROCm or Vulkan) and compare reply times.

[NX-LLM-014] Model running partly on CPU (not enough VRAM)
  Severity   : HIGH             Status: KNOWN              Observed: EXPECTED
  Symptom    : "ollama ps" shows PROCESSOR as "40%/60% CPU/GPU" and replies
               become very slow (minutes).
  Cause      : Model + context don't fit in free VRAM (other apps using the
               GPU, cards with less than 8 GB).
  Solution   : Use a smaller model (qwen3:4b), reduce llm_context to 4096
               (may worsen NX-LLM-004) or close apps using the GPU.

[NX-LLM-015] Thinking mode makes qwen3 slow
  Severity   : MEDIUM           Status: FIXED              Observed: EXPECTED
  Cause      : qwen3 "thinks" before answering by default, generating
               hundreds of extra tokens.
  Fix        : llm.py sends "think": false on Ollama's native API.
  Tips       : With LM Studio (OpenAI API) the parameter is not sent: add
               "/no_think" to the system instructions or disable reasoning in
               the LM Studio interface.

[NX-LLM-016] Automatic memory stores questions as "facts" or redundant facts
  Severity   : MEDIUM           Status: FIXED (v0.5)       Observed: YES
  Symptom    : Real case (2026-10-13): questions about CPR created 6 false,
               repeated memories, such as "The user needs to perform CPR" and
               "The user is interested in CPR".
  Cause      : Automatic extraction ran after EVERY message, also read
               NEXUS's answer (the topic became an "interest") and only
               discarded duplicates with identical text.
  Fix        : - it only runs when the user states something about themselves
                 (I, my, I'm, eu, sou, soy, tengo...) and never on questions or
                 emergencies - memory.states_fact();
               - it reads only the user's message, with an explicit prompt that
                 questions are not facts; at most 3 facts per message;
               - the same idea in other words is not stored again (80% shared
                 words); a negation counts as a correction - memory.similar().
  Tips       : Remove wrong memories with "✕" in Panel > Memory.

[NX-LLM-017] Model invents tool arguments
  Severity   : MEDIUM           Status: FIXED              Observed: YES
  Symptom    : Calls like list_events(status="pending") raised errors and the
               model retried several times.
  Fix        : tools.execute() drops parameters the function doesn't accept
               and null values before running.


[NX-LLM-018] AI handles "repeat"/"explain better" by talking, without the tool
  Severity   : LOW              Status: KNOWN              Observed: YES
  Symptom    : For long requests ("can you repeat what you just said?",
               "I didn't get anything, explain it more simply"), qwen3:8b
               answers directly without calling conversation_control.
  Impact     : In the tests the result was correct (it repeated /
               re-explained more simply / confirmed it would stay quiet).
               Actions that must act on audio (pause, stop, resume, repeat)
               are handled by the local detector (nexus/control.py), which is
               instant and doesn't depend on the model.
  Tips       : Short commands, or ones that START with "hold on", "wait a
               second", "stop talking", "be quiet"... are always recognized.
               For new expressions, edit PATTERNS/LEADING in
               nexus/control.py.

[NX-LLM-019] Ambiguous question answered with a topic from another conversation
  Severity   : HIGH             Status: FIXED (v0.4)       Observed: YES
  Symptom    : Real conversation on 2026-10-13: after questions about the
               weight of the heart, "tell me the exact values" was answered
               with "You spent R$ 18.00 on lunch and R$ 42.00 at the market".
  Cause      : (1) the history sent to the AI was the last 24 messages with
               no time limit, including a conversation about expenses from one
               hour earlier; (2) the recent-actions log ("Logged in
               'gastos'...") went into the context of every message; (3)
               "values" is ambiguous and the 8B model picked the most salient
               "value" (money).
  Fix        : - history only from the current session (since the app opened;
                 2 h of silence also ends a session) - memory.session_start();
               - action log only from the session and the last 15 minutes;
               - rule: short/elliptical questions refer to the last answer;
               - knowledge search also uses the previous question when the
                 message has fewer than 6 words.
  How to check: tests\conversation_eval.py reproduces the case with an old
               expenses session planted 3 h earlier.

[NX-LLM-020] Imprecise or contradictory values in factual questions
  Severity   : MEDIUM           Status: MITIGATED          Observed: YES
  Symptom    : "A woman's heart weighs between 250 and 350 g, similar to a
               man's" and then "250 to 300 g" (contradiction). Reference
               values: men ~280-340 g, women ~230-280 g.
  Cause      : The knowledge base had no anatomy; the model answered "from
               memory", and 8B models are imprecise with numbers. It also
               didn't say an "exact value" doesn't exist.
  Fix        : - "Anatomy" book (PT/EN/ES) with organ weights, vital signs,
                 blood, bones and reference values;
               - rule: give average and range, say when no exact value exists,
                 stay consistent and correct yourself explicitly.
  Limitation : Outside the base's topics the model may still get numbers
               wrong. Teach NEXUS reliable sources (Teach button / inbox).

[NX-LLM-021] Wrong and dangerous first-aid instructions
  Severity   : CRITICAL         Status: FIXED (v0.5)       Observed: YES
  Symptom    : Real case (2026-10-13): "preciso fazer RCP, como faço?" (how do
               I do CPR?) was answered with hands "over the xiphoid process"
               (correct: lower half of the sternum) and "CPR for 10 to 15
               minutes before stopping" (correct: don't stop until the person
               responds, help arrives or you are exhausted). 26-37 s per reply.
  Cause      : Keyword search didn't find the manual for everyday phrasing
               ("preciso fazer RCP" retrieved Existentialism; "engasgado"
               doesn't match "engasgo") and the model improvised.
  Fix        : Emergency mode (nexus/emergency.py): common emergencies in
               PT/EN/ES are recognized by dedicated patterns. The first
               message is answered instantly, without the AI, with the
               emergency number and the manual's literal protocol. Follow-up
               questions on the same topic go to the AI with the manual
               excerpt always in context and a rule to add nothing outside it.
  How to check: tests\conversation_eval.py replays the conversation (0 s
               reply, "lower half of the sternum", "don't stop").
  Important  : NEXUS does not replace professional care. Always call
               emergency services and follow the dispatcher.
  Update     : (v0.8) In the evaluation, even with the manual in the context,
               the model answered "How long can a person stay in CPR?" with
               "not more than 10 minutes... interrupt it". Emergency
               follow-up answers are no longer shown while generated:
               emergency.guard() checks them and, if they say to stop CPR or
               mention a minute limit, replaces them with the manual's literal
               line ("Don't stop until the person responds, professionals take
               over, or you're exhausted").

[NX-LLM-022] Emergency mode triggered without an emergency (false alarm)
  Severity   : LOW              Status: KNOWN              Observed: EXPECTED
  Symptom    : Figurative phrases such as "dor no peito de saudade" (chest
               pain from missing someone) show the heart-attack protocol.
  Cause      : Recognition deliberately errs on the side of caution: showing
               a protocol needlessly costs little; missing an emergency may
               cost a life. Technical contexts ("my code is bleeding memory")
               are already ignored.
  Workaround : Just keep talking; the protocol is only repeated after 10
               minutes. For new exceptions, adjust _TECH or TOPICS in
               nexus/emergency.py.
  Update     : (v0.8, seen in the evaluation) "Give me a first-aid mock
               exam" opened the protocol. Study messages (mock exam, quiz,
               test, questions, study, course...) no longer trigger
               emergency mode unless they also sound urgent ("now", "help",
               "not breathing"...): _STUDY / _URGENT.

[NX-LLM-023] Live data invented or refused (weather, news, exchange rates)
  Severity   : HIGH             Status: FIXED (v0.6)       Observed: YES
  Symptom    : In v0.6 tests, without the rule, "what are today's top news?"
               produced INVENTED headlines and "will it rain today?" was
               answered with "the forecast is not available", without looking.
  Cause      : The model answers from memory instead of calling the tool.
  Fix        : A "live data requires the tool" rule plus a safety net
               (assistant.LIVE): weather, news or currency questions without

[NX-LLM-024] Quiz/mock exam: answers stored, graded wrong or never graded
  Severity   : HIGH             Status: FIXED (v0.8)       Observed: YES
  Symptom    : In a mock exam (USMLE, 2026-10-14) NEXUS stored the answers
               with record_data (keys out of order: questao_1, questao_10,
               questao_2...), reported answers the user never gave, said
               everything was right using false facts and asked "Shall we
               start?" three times.
  Cause      : With no quiz rule, the model treated each answer as data to
               log and graded everything at the end, from memory.
  Fix        : QUIZZES rule in the prompt: grade each answer immediately
               (right or wrong, the correct answer and why), never use
               record_data for answers, only say "correct" after checking,
               ask "shall we start?" at most once. Verified in
               tests\conversation_eval.py.
  Tip        : For real exams, check answer keys in official sources; the
               local 8B model can still get specific medical facts wrong.

[NX-LLM-025] "I didn't understand" without an explanation (e.g. joke repeated)
  Severity   : MEDIUM           Status: FIXED (v0.8)       Observed: YES
  Symptom    : "I didn't get the joke" made NEXUS say "I don't think you
               understood" and repeat the same joke in other words.
  Cause      : The request sent to the model was generic ("explain more
               clearly") and did not say WHAT the user didn't understand.
  Fix        : The request now includes the user's words and asks for the
               MEANING (for a joke: the wordplay and why it is funny),
               forbidding the same sentence. The spoken intro is now "No
               problem, let me explain it another way".

[NX-LLM-026] Cloud provider: "no connection", key rejected or model doesn't use tools
  Severity   : MEDIUM           Status: KNOWN              Observed: EXPECTED
  Symptom    : In Settings > Intelligence, "Test connection" shows "No
               connection: 401/403", or the model answers but saves nothing.
  Cause      : (1) Missing, wrong or out-of-credit API key. (2) Address edited
               by hand. (3) The chosen model doesn't support tool calling, and
               without it NEXUS can't save reminders or data. (4) Some
               providers don't list models (/models); the test then says the
               model "is not in the list" even though it works.
  Solution   : Pick the provider from the list (the address is filled in),
               paste the key, click Test connection and choose a model from
               the list. Use models that support tools.
  Privacy    : With cloud providers, messages, memories and context data leave
               the computer (yellow warning on screen). The key is stored as

[NX-LLM-027] Stored "data" the user didn't ask for (e.g. "let's study JS")
  Severity   : MEDIUM           Status: FIXED (v0.12)      Observed: YES
  Symptom    : On 2026-10-14, "vamos estudar JS" (let's study JS) became "I
               saved your study strategies in the 'estudos' collection".
  Cause      : The model treated a study request as something to store.
  Fix        : Explicit rule: only store what the user asked to store;
               lessons, explanations, plans, questions and quiz answers are
               conversation, not data. Also: when the user says their name,
               the AI updates the profile. Verified in
               tests\conversation_eval.py ("vamos estudar JS").

[NX-LLM-028] Answer cut off or confused in a long conversation (context overflow)
  Severity   : HIGH             Status: FIXED (v0.15.1)    Observed: YES
  Symptom    : In a long conversation a quiz question stopped at "d)" and the
               answer "Letra A" was handled as logging an old expense.
  Cause      : Rules + 34 tools = 3,111 tokens; with the history the prompt
               went past 8,192 and Ollama dropped its start (the rules).
  Fix        : History budget (up to 2,500 tokens, 1,200 left for the answer);
               oldest exchanges go first and long old answers are shortened.
               Tested in tests\test_units.py.

[NX-LLM-029] Slow answer right after another (cache evicted by a background job)
  Severity   : MEDIUM           Status: FIXED (v0.15.1)    Observed: YES
  Cause      : The automatic title and memory extraction used a different
               prompt; Ollama has a single cache, so the next message re-read
               ~5k tokens (38.5 s measured just for reading).
  Fix        : Background jobs reuse the conversation's exact prompt prefix
               (assistant.side_messages).

[NX-LLM-030] Slow answers in long conversations (sliding history without cache)
  Severity   : MEDIUM           Status: MITIGATED (v0.15.1) Observed: YES
  Cause      : The history window moved one message per turn, changing the
               start of the prompt; Ollama re-read almost everything (~245
               tokens/s on the RX 6600 XT).
  Fix        : Anchored window that jumps when full: 19.2 s -> 14.4 s per
               answer from the 9th message on (tests\bench_long_conversation.py).
  Limit      : Each message's context block (time, knowledge excerpts) isn't
               kept in the history, so the last exchange is still re-read
               (~4-9 s). Future optimization.

[NX-LLM-031] API error shown as "start Ollama" (key, credits, limit)
  Severity   : MEDIUM           Status: FIXED (v0.15.1)    Observed: YES
  Fix        : llm.classify() tells apart rejected key (401/403), no credits or
               payment (402 / "quota"), usage limit (429), unknown model (404),
               provider down (5xx), no connection and offline mode, each with
               its own message in the 3 languages. The provider's code and
               answer go to logs/nexus.log, without the key.

[NX-LLM-032] Answer stuck in an endless loop (the same sentence over and over)
  Severity   : HIGH             Status: FIXED (v0.15.1)    Observed: YES
  Symptom    : In the evaluation, "tell me a joke" repeated the same passage until
               the context was full: 43 minutes for one answer.
  Fix        : ~1,200-token cap per answer and a repetition detector
               (assistant._looping / _trim_loop): the loop is cut and the answer
               ends at the first complete sentence. Tested in tests\test_units.py.

[NX-LLM-033] Last answer re-read on every message (incomplete Ollama cache)
  Severity   : MEDIUM           Status: EXPERIMENTAL       Observed: YES
  Symptom    : Even with the anchored window (NX-LLM-030), every answer started
               by re-reading the previous question and answer.
  Cause      : Ollama's qwen3 template adds " /no_think" to the LAST question
               only and an empty <think> block before the answer; both vanish
               once the exchange becomes history. The cache stopped there and
               the whole previous answer was re-read.
  Fix        : Experimental, off by default (settings.json:
               "llm_raw_prompt": true): NEXUS writes the qwen3 prompt itself
               (llm.render_qwen3, raw /api/generate), identical on every turn,
               so the cache covers up to the last generated token. In the v0.15.5
               tests the average stayed within noise, because the previous
               question still changes (its context block is not kept in the
               history); keeping that block filled the window and was slower.
               Measured with tests/bench_long_conversation.py.

[NX-LLM-034] "I can't open the site / play the song / read the book"
  Severity   : LOW              Status: EXPECTED (v0.15.5) Observed: PLANNED
  Cause      : In user mode, Workspace, Library, Skills and Browser are beta
               features, off by default: they leave the screen and the AI's tools.
  Solution   : Settings → Beta: turn the feature on (or use Developer mode,
               which turns them all on).

[NX-LLM-035] Very slow prompt reading on AMD cards (Vulkan + Flash Attention)
  Severity   : HIGH             Status: WORKAROUND         Observed: YES
  Symptom    : Every answer takes 5-20 s to start, even with the whole model on
               the graphics card.
  Cause      : With an old AMD driver Ollama logs "AMD driver is too old"
               (server.log) and uses Vulkan instead of ROCm. On that path, with
               Flash Attention on, the RX 6600 XT read the prompt at 75 tokens/s;
               with it off, at 265 tokens/s (3.5x), while generation dropped from
               33 to 23 tokens/s. Measured with 5,500 tokens.
  Solution   : Settings > Performance > Graphics card > "Optimize Ollama for this
               card" (creates OLLAMA_FLASH_ATTENTION=0 in your user and restarts
               Ollama; reversible). Measured in a conversation: 16.4 s -> 11.9 s
               per answer (-27%; on Ollama 0.40.5: 14.2 s -> 9.0 s, -37%), with
               ~0.5 GB of the model moving to RAM.
               Updating the driver doesn't help: with Adrenalin 26.8.1 (the
               latest in 2026-10) the warning stays, because Ollama has no ROCm
               for the RX 6600 XT (gfx1032) on Windows.

[NX-LLM-036] Reminder set for the day after tomorrow ("tomorrow" became the 17th)
  Severity   : HIGH             Status: FIXED (v0.15.5)    Observed: YES
  Symptom    : In the evaluation, after a long conversation, "remind me tomorrow
               at 10" was saved one day too late.
  Cause      : The context calendar was an unlabelled list (tomorrow, the day
               after, ...) and the model took the second entry.
  Fix        : The context says "Tomorrow = <day>; day after tomorrow = <day>".

[NX-LLM-037] Slow first answer after switching language
  Severity   : MEDIUM           Status: FIXED (v0.16.1)    Observed: YES
  Symptom    : After switching to English a simple "Hello" took ~26 s; the next

[NX-LLM-038] The AI said it opened (or would open) a menu and nothing opened
  Severity   : MEDIUM           Status: FIXED (v0.16.5)    Observed: YES
  Symptom    : In the evaluation, "I want to change the ring colour, take me

[NX-LLM-039] Training: general facts disappeared or were judged without evidence
  Severity   : HIGH             Status: FIXED (v0.17.5)    Observed: YES
  Symptom    : While testing training mode (beta), "Jupiter is the largest

[NX-LLM-040] Training: the AI asked "shall I save it?" after every lesson

[NX-LLM-041] Live questions: the AI called the tool again (answer in two rounds)

[NX-LLM-042] "Done: AMD theme." without changing anything (the AI didn't call set_preference)

[NX-VOZ-001] Microphone doesn't respond on first use (Whisper download)
  Severity   : MEDIUM           Status: KNOWN              Observed: EXPECTED
  Symptom    : Clicking the microphone shows "Preparing the voice model...".
  Cause      : The Whisper model is downloaded only on first use (tiny
               ~75 MB, base ~145 MB, small ~480 MB, medium ~1.5 GB) so the
               app's first launch isn't delayed.
  Solution   : Wait for the download (requires internet once) and click
               again.
  Tips       : For offline PCs, open NEXUS once with internet and use voice
               to download the model; it stays cached
               (%USERPROFILE%\.cache\huggingface). If the download fails the
               error appears in the chat; switch to "base" in Settings.

[NX-VOZ-002] Wrong microphone selected (e.g. DroidCam)
  Severity   : HIGH             Status: FIXED (v0.10)      Observed: YES
  Symptom    : NEXUS doesn't react to speech or records silence.
  Cause      : NEXUS uses Windows' DEFAULT input device. On the reference PC
               the default was "Microphone (DroidCam Audio)", a virtual
               microphone.
  Solution   : Windows Settings > System > Sound > Input: choose the real
               microphone as default and restart NEXUS.
  Improvement: Add device selection to NEXUS Settings
               (sounddevice.query_devices).
  Fix        : (v0.10) Settings > Microphone > Input device lists the
               microphones (without the virtual "Sound Mapper") and switches
               immediately, no restart. If the chosen one is unplugged, NEXUS
               falls back to the Windows default. If your microphone is not in
               the list, Windows doesn't see it: check that it is connected
               and enabled in Windows Settings > Sound.

[NX-VOZ-003] Wake word "Nexus" not recognized / false triggers
  Severity   : MEDIUM           Status: FIXED (v0.8)       Observed: YES
  Symptom    : Saying "Nexus" doesn't activate it; or NEXUS answers side
               conversations.
  Cause      : Whisper transcribes "Nexus" in various ways ("Néxus",
               "Nexos", "Next us"). The WAKE_RE regex in voice.py covers the
               most common variants.
  Tips       : Say "Nexus" and pause briefly before the command. Use the
               "small" model (more accurate than "base"/"tiny"). If a new
               variant shows up, add it to WAKE_RE. In noisy places prefer
               the microphone button or Ctrl+Space.
  Fix        : (v0.8) WAKE_RE also covers "Nécsus", "Neksus", "Nexis",
               "Nek us"; Whisper gets an initial vocabulary with "NEXUS" and
               the user's name, and a fixed language. Measured with
               tests\bench_voice.py: "Nexus" recognized 2/6 -> 6/6.

[NX-VOZ-004] Recording doesn't start or doesn't stop (voice detection)
  Severity   : MEDIUM           Status: FIXED (v0.8)       Observed: YES
  Symptom    : State stays "LISTENING" forever, or speech is not captured.
  Cause      : Voice detection uses signal energy with a threshold adapted
               to ambient noise. Fans, music or a microphone gain that is too
               low/high interfere.
  Tips       : Recording ends after ~0.75 s of silence or 30 s maximum. Set
               the microphone volume in Windows to ~70-80%. Use a headset in
               noisy environments.
  Fix        : (v0.8) The energy detector was replaced by Silero VAD (a
               neural network that tells voice from noise, ~0.2 ms per frame,
               already shipped with faster-whisper). Measured with fan noise:
               energy closed 0/6 recordings (stayed "listening" up to 30 s);
               Silero closed 6/6, right after speech ended (0.7 s pause).

[NX-VOZ-005] NEXUS hears its own voice (echo)
  Severity   : MEDIUM           Status: MITIGATED          Observed: EXPECTED
  Cause      : Speakers picked up by the microphone while NEXUS talks.
  Mitigation : Since v0.3, while NEXUS speaks the microphone stays on but
               only accepts short control commands ("pause", "stop", "hold
               on...") up to 4 s long; everything else is ignored (see
               NX-VOZ-013). There is a 250 ms margin after speech ends.
               v0.18.1: what is heard right after and repeats a stretch of
               what NEXUS just said is discarded (see NX-VOZ-019).
  Tips       : Use headphones; mute the AI voice from the dock if needed.

[NX-VOZ-006] No Spanish voice / voice in the wrong language
  Severity   : MEDIUM           Status: PENDING            Observed: YES
  Symptom    : Spanish replies read with the Portuguese/English voice.
  Cause      : Only installed SAPI voices are used. The reference PC has Maria
               (pt-BR, female), Daniel (pt-BR, male, OneCore) and Zira (en-US,
               female); none in Spanish.
  Solution   : Windows Settings > Time & language > Speech > Add voices >

  Note       : Since v0.2 NEXUS reads both "Desktop" and "OneCore" Windows

[NX-VOZ-007] Speech synthesis stops working after a while
  Severity   : MEDIUM           Status: FIXED              Observed: EXPECTED
  Cause      : Known pyttsx3 issue with repeated runAndWait() calls on some
               systems.
  Fix        : pyttsx3 was replaced by our own engine (nexus/tts.py): SAPI
               renders audio to memory and sounddevice plays it. If speech
               fails, the error is kept in Speaker.error and the app goes on.

[NX-VOZ-008] Slow transcription
  Severity   : LOW              Status: KNOWN              Observed: EXPECTED
  Cause      : Whisper runs on the CPU (CTranslate2 does not use AMD GPUs on
               Windows).
  Tips       : Use "base" in Settings for speed and "small" for accuracy.
               Short sentences are transcribed faster.

[NX-VOZ-009] "Mute" only stops at the end of the current sentence
  Severity   : LOW              Status: FIXED              Observed: EXPECTED
  Cause      : With pyttsx3, interruption only happened between sentences.
  Fix        : With the new engine, Esc / "mute" call sounddevice.stop() and
               cut the audio immediately.

[NX-VOZ-010] Male voice sounds androgynous in some languages
  Severity   : LOW              Status: KNOWN              Observed: YES
  Symptom    : With "Voice: male" in English, speech sounds between male and
               female.
  Cause      : No male voice is installed for that language (the reference PC
               only has Zira for English). NEXUS uses the available voice with

[NX-VOZ-011] "J.A.R.V.I.S"/"Robot" voice effect sounds muffled or too metallic
  Severity   : LOW              Status: KNOWN              Observed: EXPECTED
  Cause      : Effects vary a lot with the speaker. Since v0.4 "J.A.R.V.I.S"

  Tips       : Use "J.A.R.V.I.S" day to day and "Robot" only for show.

[NX-VOZ-012] Commands during speech fail with loudspeakers
  Severity   : MEDIUM           Status: KNOWN              Observed: EXPECTED
  Symptom    : "Pause" said while NEXUS speaks is not recognized.
  Cause      : Without echo cancellation, the microphone captures NEXUS's
               voice together with the user's and Whisper transcribes the mix.
  Solution   : Use headphones; or use the dock buttons (interrupt) and Esc.
               Future improvement: acoustic echo cancellation (AEC).

[NX-VOZ-013] Sentence said while NEXUS speaks is ignored
  Severity   : LOW              Status: KNOWN              Observed: YES
  Expected behavior: while speaking, only control commands are accepted
               (pause, stop, repeat, I didn't understand...). This prevents
               NEXUS from answering itself through the echo.
  Workaround : Say "pause" or "stop" and then ask, or wait for the speech to
               end. While paused, the microphone accepts any sentence again.

[NX-VOZ-014] "Audio only" mode answers nearby conversations / TV
  Severity   : MEDIUM           Status: KNOWN              Observed: EXPECTED
  Cause      : Since v0.3 audio mode listens continuously without requiring
               the word "Nexus".
  Solution   : Enable "Only answer when I say Nexus" in Settings, mute the
               microphone from the dock when not in use, or use "messages
               only" mode.

[NX-VOZ-015] "Smoker's device" (electrolarynx) voice, hard to understand
  Severity   : HIGH             Status: FIXED (v0.4)       Observed: YES
  Cause      : The J.A.R.V.I.S effect (v0.2-v0.3) multiplied the voice by a
               45 Hz tone (ring modulation), plus a metallic comb and a cut
               above 7 kHz. Measured: buzz 16 to 24 times above the natural
               voice and no consonant emphasis.
  Fix        : New effect without modulation: 2-5 kHz presence boost, 1.2 ms
               sheen and a short room. Measured: buzz 1.2-1.5x, fidelity
               0.88 -> 0.97, consonant energy ~2x.
  How to check: tests\test_units.py compares it with the old modulation.

[NX-VOZ-016] Name pronounced "NÊXUS" (or spelled "N, E, X, U, S")
  Severity   : LOW              Status: FIXED (v0.4.1)     Observed: YES
  Cause      : Portuguese/Spanish voices read "Nexus" with a closed E and
               spell out "N.E.X.U.S". The name must sound as in English/
               Spanish: "NEK-sus", no vowel between K and S.
  Fix        : The text sent to the voice replaces the name with a spelling
               chosen by acoustic measurement (log-mel spectrum + DTW against
               the English voice saying "Nexus"): "Nécsus" for the male voice
               (Daniel) and "Néc-sus" for the female one (Maria). "Néxus"
               (v0.4.0) and "Néquissus" were the farthest. The screen still
               shows N.E.X.U.S (tts.pronounce()).
  Tips       : For a new voice, try spellings and adjust _SPOKEN_NAME in
               nexus/tts.py; always check by ear.

[NX-VOZ-017] Poor recognition: wrong words, wrong language, invented sentences
  Severity   : HIGH             Status: FIXED (v0.8)       Observed: YES
  Symptom    : Short sentences transcribed in another language or with wrong
               words; with noise, sentences nobody said appeared ("Thank
               you.", "Subtitles by the community...").
  Cause      : Language on "auto" (Whisper guesses it from 1-2 s of audio),
               greedy search (beam 1), low-gain microphones and noise
               segments sent to Whisper.
  Fix        : Fixed language (the one chosen in Settings or the profile's),
               beam 5, initial vocabulary (NEXUS + name), volume
               normalization with a gain cap (8x) and dropping segments
               Whisper itself flags as "no speech". Measured with
               tests\bench_voice.py (20 noisy sentences): word error rate
               24.5% -> 12.1%, and faster (3.2 s -> 2.0 s per sentence).
  Tip        : If you speak another language with NEXUS, choose it in
               Settings > Language.

[NX-VOZ-018] Links read out letter by letter
  Severity   : MEDIUM           Status: FIXED (v0.14)      Observed: YES
  Symptom    : Answers with links (news, Wikipedia) were spoken character by
               character: "h t t p s colon slash...".
  Fix        : When spoken, each link becomes the site's name
               (pt.wikipedia.org -> "wikipedia", g1.globo.com.br -> "globo");
               Markdown links only speak their text. The screen still shows
               the full link. Tested in tests\test_units.py.

[NX-VOZ-019] NEXUS talked by itself: it heard its own voice and took it as yours
  Severity   : HIGH             Status: FIXED (v0.18.1)    Observed: YES
  Symptom    : In audio mode, with the user silent, messages like "Cara
               sorrindo de boca aberta e olha o sonho" showed up and NEXUS
               answered them.
  Cause      : (1) The Windows voice read emojis by name ("😄" -> "grinning
               face with big eyes"). (2) With a delayed microphone (DroidCam
               over Wi-Fi) or loudspeakers, the end of NEXUS's speech reached the
               microphone after it had stopped talking, outside the echo
               protection (NX-VOZ-005).
  Fix        : Emojis are not read aloud. NEXUS keeps what it said in the last
               seconds; a phrase heard up to 2.5 s after it stopped that repeats
               a stretch of 4+ of its words is discarded (later, only an almost
               literal repetition). Tested with real audio: 3/3 echoes
               discarded, 3/3 user replies accepted (including "conta uma
               piada" after "posso contar uma piada").

[NX-VOZ-020] Invented phrases with nobody talking ("Você tem um clima?" 3x, subtitle credits)
  Severity   : MEDIUM           Status: FIXED (v0.18.1)    Observed: YES
  Cause      : On noise Whisper sometimes "invents" speech: subtitle credits
               ("Legendas pela comunidade Amara.org") or one sentence repeated.
  Fix        : While listening continuously (not push-to-talk), low-confidence
               or repetitive segments are dropped, as are subtitle credits and
               the same sentence 3 times. Pure noise: 3/3 without text.

[NX-DAT-001] Knowledge base doesn't find an existing topic
  Severity   : MEDIUM           Status: KNOWN              Observed: EXPECTED
  Cause      : Search is keyword based (SQLite FTS5 + BM25), not meaning
               based. Synonyms ("heart attack" vs "myocardial infarction")
               and questions without the text's terms may fail.
  Tips       : Use terms present in the text. When teaching something,
               include synonyms in the content. Use the "Knowledge" panel
               search to test. Planned improvement: semantic search with
               embeddings (nomic-embed-text via Ollama).

[NX-DAT-002] Imported PDF has no text ("Could not extract text")
  Severity   : LOW              Status: KNOWN              Observed: EXPECTED
  Cause      : Scanned PDF (image) without a text layer.
  Solution   : Run the PDF through OCR (e.g. OCRmyPDF) or convert it to .txt
               before importing.

[NX-DAT-003] "Invalid date" when creating an event/task
  Severity   : LOW              Status: FIXED              Observed: YES
  Cause      : The model sent dates as text ("tomorrow") instead of ISO.
  Fix        : The tool returns the error with the expected format
               (YYYY-MM-DDTHH:MM) and the model corrects it in the next
               round.

[NX-DAT-004] Reminder did not fire
  Severity   : MEDIUM           Status: KNOWN              Observed: EXPECTED
  Cause      : (a) NEXUS was closed at that time: reminders more than 1 h
               late are discarded on launch, to avoid an avalanche of old
               alerts. (b) The scheduler checks every 15 s.
  Tips       : Keep NEXUS open (start with Windows is on the roadmap). Check
               the event in the Schedule panel.

[NX-DAT-005] nexus.db file in use / database locked
  Severity   : LOW              Status: KNOWN              Observed: YES
  Symptom    : The data folder cannot be deleted or copied.
  Cause      : Another NEXUS process (or the executable) is still open.
  Solution   : Close every NEXUS window; in Task Manager end any remaining
               "NEXUS.exe"/"python.exe".
  Tips       : For backups, copy nexus.db with the app closed.

[NX-DAT-006] Seed books re-indexed or duplicated
  Severity   : LOW              Status: KNOWN              Observed: EXPECTED
  Cause      : Re-indexing happens when a file in nexus/seed changes its
               modification date (by design). Renaming a file creates a new
               document and keeps the old one.
  Solution   : Remove the old document in the "Knowledge" panel (only
               non-seed documents have "✕") or delete data\nexus.db to rebuild
               the base (DELETES all data).

[NX-DAT-007] File in the inbox folder is not re-imported
  Severity   : LOW              Status: KNOWN              Observed: EXPECTED
  Cause      : After import the file is renamed to *.learned.
  Solution   : Remove the ".learned" extension to import it again on the
               next boot, or use the "Import files" button.

[NX-DAT-008] "Shall we continue...?" greeting doesn't show / shows only once
  Severity   : LOW              Status: KNOWN              Observed: YES
  Expected behavior: NEXUS only says "Hello {name}, shall we continue
               {topic}?" if the user ASKED to be reminded on the next start
               (remind_next_session tool). The note is consumed once spoken;
               later starts go back to "what do we have for today?". The full
               introduction happens only the first time ("introduced" flag in
               the state table).
  If it doesn't show: check the LOG panel for "Lembrar ao abrir: ..."; if
               it's missing, the model didn't call the tool (NX-LLM-003): ask
               explicitly, e.g. "next time I open NEXUS, remind me to continue
               project X".
  To see the introduction again: delete the "introduced" row from the state
               table (or use a new NEXUS_HOME).

[NX-DAT-009] Old conversation missing from the list or without title/description
  Severity   : LOW              Status: KNOWN              Observed: EXPECTED
  Symptom    : A conversation is missing from Conversations > Threads, or it
               only shows the beginning of the first question, with no
               description.
  Cause      : (1) The list only shows conversations where you wrote
               something (the greeting alone doesn't count). (2) The title and
               description are written by the AI in the background after the
               1st answer and refined at the 4th exchange; if the AI was off
               or the answer was interrupted, the provisional title stays.
               (3) Conversations from before v0.9 were split automatically by
               2 h pauses and only have the provisional title.
  Solution   : Use the pencil (✎) on the card to rename it. The "All" tab
               shows every message, including those not in the list.

[NX-DAT-010] Answer uses a topic from another conversation
  Severity   : MEDIUM           Status: MITIGATED          Observed: EXPECTED
  Cause      : Only the OPEN conversation is sent to the AI. When you reopen
               an old conversation it becomes the context again; short
               questions ("and for a woman?") then refer to it.
  Tips       : To change subject, use "New conversation" on the right edge.
               After 2 h without messages, the next message already opens a
               new conversation (same rule as v0.5, NX-LLM-019).

[NX-DAT-011] Reminder not spoken / not shown / came only once
  Severity   : MEDIUM           Status: KNOWN              Observed: EXPECTED
  Cause      : (1) Reminders only work while NEXUS is open (it may be
               minimized). (2) During quiet hours they only go to the
               notification center (bell). (3) "Speak reminders" is off or the
               AI voice is muted. (4) Each lead time fires once; if NEXUS
               opened late, only the closest one is announced. (5) Lead times
               already past when the appointment was created don't fire (an
               event in 30 min won't say "in 1 hour"). (6) Items more than 1
               hour late are dropped. (7) "Remind me to drink water at 3 pm"
               only fires at the time.
  Solution   : Settings > Notifications: choose the lead times and use "Test
               notification". The bell on the top bar lists everything that
               was announced.

[NX-DAT-012] Restore backup: nothing changed / data "vanished" after restoring
  Severity   : MEDIUM           Status: KNOWN              Observed: EXPECTED
  Cause      : (1) A restore is only applied when NEXUS is REOPENED (replacing
               the open database is unsafe). (2) It brings back the state of
               the backup's day: anything done afterwards isn't in it.
  Solution   : Close and reopen NEXUS. The data from before the restore is kept
               in backups/before-restore-<date> (copy nexus.db back to the data
               folder, with NEXUS closed, to undo).

[NX-DAT-013] File or book doesn't open / "no text found"
  Severity   : MEDIUM           Status: KNOWN              Observed: EXPECTED
  Cause      : (1) Scanned PDF (images only): it has no text; turn the pages
               into images and attach them (Windows OCR reads images).
               (2) Formats not supported yet: RAR, old .doc, .xlsx.
               (3) Password-protected PDF. (4) Image text in a language
               without the Windows OCR pack (Settings > Time & language).
  Solution   : Save as a text PDF, DOCX or TXT. Big files are reduced to the
               passages that match the question.

[NX-UI-010] Windows notification doesn't appear

[NX-WRK-001] The AI says it created/changed a file, but nothing changed
  Severity   : MEDIUM           Status: MITIGATED          Observed: YES
  Symptom    : The answer says "I created" / "I'll fix it", but the file list
               and Changes don't change.
  Cause      : The model sometimes announces the action instead of calling the
               tool (v0.11 evaluation: "I'll fix it" after a failing test,
               without fixing).
  Fix        : Two safety nets (assistant._needs_file_tool): claiming a change
               without a tool, or ending with a promise ("I'll fix it"), sends
               the request back to the model to act immediately. Verified in
               tests\workspace_eval.py.
  Tip        : The CHANGES panel only shows what really changed.

[NX-WRK-002] "Outside the workspace": path refused
  Severity   : LOW              Status: KNOWN              Observed: YES
  Cause      : Intentional protection. The AI only uses paths relative to the
               workspace folder; "..", "C:\...", "~" and the internal .nexus
               folder are refused. Tested in tests\test_units.py.
  Solution   : To work with outside files, copy them into the workspace folder
               ("Open folder" button on the top bar).

[NX-WRK-003] Command doesn't run, takes long or waits for confirmation
  Severity   : MEDIUM           Status: KNOWN              Observed: EXPECTED
  Cause      : (1) Every command needs your confirmation; without an answer in
               3 minutes it is denied. Esc also denies. (2) Commands have a
               120 s limit (servers and programs that never end are stopped).
               (3) The command runs in the Windows Command Prompt, in the
               workspace folder: the program (python, node, git...) must be
               installed and on the PATH.
  Solution   : For long processes, run them yourself via "Open folder". If
               you deny, tell the AI what you'd rather do.

[NX-WRK-004] Undo didn't return to the expected state
  Severity   : LOW              Status: KNOWN              Observed: EXPECTED
  Cause      : Undo works per file: each write, edit or delete keeps the
               previous version in .nexus/history. Effects of COMMANDS (files
               created by a program, installed packages) are not in the
               history and can't be undone.
  Solution   : Use "undo" on the right change in the panel (newest first). Old
               versions stay in .nexus/history inside the folder. Deleted
               workspaces go to workspaces/.trash.

               read-only and covers the next 30 days; syncs every 30 min.
  Tips       : Google Calendar: calendar settings > Integrate calendar >
               "Secret address in iCal format". To sync now, say "update my
               calendar". Don't share that link: it grants read access to your
               calendar.

[NX-INT-007] Wrong city for weather/clock ("New York" became York, Nebraska)
  Severity   : MEDIUM           Status: FIXED (v0.18.0)    Observed: YES
  Cause      : Open-Meteo's city search looks the name up in the requested
               language; in Portuguese "New York" is "Nova Iorque" and the first
               result was York (USA) or an English village.
  Fix        : Searches in NEXUS's language and in English and picks the exact
               name with the largest population. Places are kept for 30 days.

[NX-INT-008] First answer after waking from suspended mode takes ~16 s
  Severity   : LOW              Status: KNOWN              Observed: YES
  Cause      : To free the graphics card for the game, the model leaves the VRAM
               (6.1 GB on an RX 6600 XT). When NEXUS wakes it loads again.
  Tips       : NEXUS reloads in the background as soon as it wakes; going back
               to the window before asking hides the wait. To never suspend:
               Settings > Apps and media > "Stay active".

[NX-INT-009] "What's playing?" doesn't find the player
  Severity   : LOW              Status: KNOWN              Observed: EXPECTED
  Cause      : NEXUS reads Windows' media controls. Players that don't register
               there (some sites, old players) don't show up, and the media keys
               go to the player Windows considers current.
  Tips       : Spotify, LiMusic, Chrome/Edge/Brave (YouTube) and the Media
               Player work. If nothing responds, press play once in the player
               so Windows registers it.

[NX-ENV-001] requirements.txt ignored by Git
  Severity   : HIGH             Status: FIXED              Observed: YES
  Cause      : The "*.txt" rule in .gitignore (which protects
               "NEXUS INFOS.txt") also ignored requirements.txt and these
               documents.
  Fix        : Exceptions "!requirements.txt", "!erros.txt", "!errors.txt"
               and "!errores.txt".
  Tips       : When creating new .txt files that belong in the repository,
               add the matching exception.

[NX-ENV-002] setup.ps1 / build.ps1 blocked by PowerShell policy
  Severity   : MEDIUM           Status: KNOWN              Observed: EXPECTED
  Symptom    : "Running scripts is disabled on this system".
  Solution   : powershell -ExecutionPolicy Bypass -File setup.ps1

[NX-ENV-003] Dependencies not supported on the Python version
  Severity   : HIGH             Status: KNOWN              Observed: EXPECTED
  Situation  : Tested with Python 3.14.8 and the versions pinned in
               requirements.txt.
  Tips       : If pip install fails compiling packages (numpy, ctranslate2),
               use Python 3.12, which has broad prebuilt-wheel support. The
               whole team should use the same version.

[NX-ENV-004] Antivirus blocks or removes NEXUS.exe
  Severity   : MEDIUM           Status: KNOWN              Observed: EXPECTED
  Cause      : Unsigned PyInstaller executables sometimes trigger false
               positives.
  Solution   : Add an exception for the dist\NEXUS folder or distribute the
               source with setup.ps1. Definitive fix: sign the executable and
               build an installer (Inno Setup).

[NX-ENV-005] Executable opens and closes / module not found
  Severity   : HIGH             Status: FIXED              Observed: EXPECTED
  Cause      : PyInstaller doesn't detect dynamic imports (comtypes COM
               interfaces used by SAPI voice, faster-whisper data).
  Fix        : build.ps1 includes the required --collect-all, --collect-submodules
               and --add-data flags. Build tested: starts, indexes the
               knowledge base and opens the local bridge.
  Tips       : When adding a dependency, build and run dist\NEXUS\NEXUS.exe
               before distributing. To see errors, build temporarily without
               --windowed.

[NX-ENV-006] Port 11434 busy or two Ollama instances running
  Severity   : MEDIUM           Status: KNOWN              Observed: EXPECTED
  Symptom    : "ollama serve" fails with "address already in use".
  Cause      : Ollama is already running from the system tray.
  Solution   : There's no need to run "ollama serve" manually if the Ollama
               icon is in the tray. To restart it, quit from the icon and
               open it again.


[NX-ENV-007] Test data showed up in the user's real data
  Severity   : HIGH             Status: FIXED (v0.4)       Observed: YES
  Symptom    : Profile "Alex Martins", expenses, appointments and memories the
               user never created (e.g. "cats Pixel and Byte").
  Cause      : A team test script ran without the NEXUS_HOME variable and
               wrote into .\data (the real folder) instead of a temporary one.
  Fix        : Tests live in tests/ and import tests/_isolated.py first, which
               creates a temporary folder and REFUSES to run if NEXUS points
               elsewhere. The data/ folder was reset (backup in
               data_backup_20261013-2101/).
  Tips       : Never test with the real folder; to inspect real data, open a
               COPY of nexus.db.

[NX-ENV-008] Each AI call took ~2 s longer ("localhost" on Windows)
  Severity   : MEDIUM           Status: FIXED (v0.6)       Observed: YES
  Cause      : On Windows "localhost" resolves to IPv6 (::1) first; Ollama only
               listens on IPv4, so each connection waited ~2 s before trying
               127.0.0.1. Measured: 2.08 s with localhost vs 0.008 s with
               127.0.0.1. Each reply makes 1 to 4 calls.
  Fix        : The default is now http://127.0.0.1:11434/v1 and the client
               replaces "localhost" automatically (old settings included).
  Tips       : Always use 127.0.0.1 for local servers (LM Studio:
               http://127.0.0.1:1234/v1).

[NX-ENV-009] Slow AI: part of the model off the graphics card / "Full power" unavailable
  Severity   : MEDIUM           Status: KNOWN              Observed: YES
  Measured   : tests\bench_hardware.py, RX 6600 XT 8 GB, qwen3:8b: context
               8192 -> 5.75 GB, 100% on the card, writes 35 tok/s; 12288 ->
               92% on the card, 31 tok/s; 16384 -> 85%, 25 tok/s and reading
               2x slower. Only ~6.2 GB of the 8 GB are free.
  Cause      : If model + context don't fit in the card's memory, Ollama puts
               layers on the processor and everything slows down.
  Solution   : Settings > Performance: "Balanced" uses 8192 (fits 8 GB
               cards). "Full power" only appears if the whole model fits with
               at least 8192 (cards of ~8 GB or more) and with 16 GB of RAM;
               on 12 GB+ cards it uses larger contexts. Close games/video
               editors to free the card's memory.

[NX-ENV-010] No dedicated graphics card: very slow answers
  Severity   : HIGH             Status: KNOWN              Observed: YES
  Measured   : Processor only (Ryzen 5 5600G): writes 7.5 tok/s and reads
               47 tok/s, ~5x slower than on the card (40 tok/s). A typical
               answer takes ~15-60 s.
  Solution   : Use the "Economy" profile (context 4096, lighter voice). See
               the requirements in the README: minimum 16 GB of RAM and an
               8-thread processor; recommended a graphics card with 8 GB.

[NX-ENV-011] "NEXUS is already open" when starting the program
  Severity   : LOW              Status: KNOWN              Observed: YES
  Cause      : v0.13 protection: only one NEXUS at a time (two fought over the
               microphone, the database and the AI). The window may be
               minimized or on another Windows virtual desktop.
  Solution   : Look for NEXUS on the taskbar. If it froze, end "NEXUS.exe" in
               Task Manager and open it again.

[NX-ENV-012] The API key is gone (another PC or Windows user)
  Severity   : LOW              Status: KNOWN              Observed: EXPECTED
  Cause      : Since v0.13 the key is encrypted by Windows (DPAPI) and only the
               same user on the same PC can read it. When the data folder is
               copied or a backup is restored on another PC, it can't be read.
  Solution   : Settings > Intelligence: paste the key again and save.

[NX-ENV-013] Automatic mode picked the wrong mode (unstable internet)
  Severity   : LOW              Status: KNOWN              Observed: EXPECTED
  Cause      : Automatic mode measures the internet every 5 minutes (and again
               when a lookup fails); short drops between measurements aren't
               seen right away.
  Solution   : Hover the chip on the top bar to see the last measurement
               (latency and speed). To fix the behaviour, choose Offline,
               Hybrid or Online in Settings > Performance.

[NX-ENV-014] ROCm forced on an unsupported card sends the AI to the processor
  Severity   : MEDIUM           Status: KNOWN              Observed: YES
  Symptom    : With OLLAMA_VULKAN=0 (and even HSA_OVERRIDE_GFX_VERSION=10.3.0,
               the Linux trick) on an RX 6600 XT, Ollama logs "no ROCm-capable
               device is detected" and runs on the processor: 9.1 tokens/s with
               0% on the card, against 35.6 tokens/s on Vulkan.
  Cause      : The ROCm shipped with Ollama for Windows has libraries for some
               chips only (gfx906, gfx1030, gfx1100-1102, gfx1150/1151,
               gfx1200/1201); the RX 6600 XT is gfx1032, and Windows ignores
               HSA_OVERRIDE_GFX_VERSION.
  Fix        : NEXUS reads the chip list from the installed Ollama and offers
               ROCm only where it works (Settings > AMD > AI backend). On other
               cards, Vulkan.
